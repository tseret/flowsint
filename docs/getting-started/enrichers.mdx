### What is an Enricher?

An enricher is an operation that, starting from an input element A (source entity), produces one or more elements B (target entities) by applying a search or correlation method called a pivot.

Example:

```bash
A = my.domain.com (domain name)
    ↓
p = “DNS resolution” (pivot)
    ↓
B = 12.23.34.45 (IP address)
```

That said, a pivot is the method or technical process used to derive B from A. The pivot defines how the transformation obtains its result (e.g., DNS resolution, WHOIS lookup, API query, etc.).

Example:

```bash
DNS Resolution → domain → IP
    ↓
WHOIS Lookup → IP → owner
    ↓
Reverse Image Search → image → web pages containing that image
```

Flowsint comes with a bunch of prebuilt enrichers, divided into multiple categories. Those enrichers can use standard pivots that your machine can support by default (DNS resolution, WHOIS request, etc.) and some other that depend on external tools. 

Those can be : 

- Native : DNS resolutions, Whois, etc.
- Docker tools: [subfinder](https://github.com/projectdiscovery/subfinder), [asnmap](https://github.com/projectdiscovery/asnmap), etc.
- Python tools: [sherlock](https://github.com/sherlock-project/sherlock), [maigret](https://github.com/soxoj/maigret), [reconurge/recontrack](https://github.com/reconurge/recontrack), [reconurge/reconcrawl](https://github.com/reconurge/reconcrawl), [reconurge/reconspread](https://github.com/reconurge/reconspread), etc. 
- External services (paid or free): [shodan](https://www.shodan.io/), [whoxy](https://www.whoxy.com/), [whoisxmlapi](https://www.whoisxmlapi.com), etc.

# Infrastructure capabilities

The **Enrichers** catalog shows readable purpose, provider, credential readiness,
reviewed passive/active behavior, freshness, and known output limits. Unreviewed
behavior is labeled unknown. Catalog metadata does not authorize copilot use;
the copilot maintains a separate explicit passive allowlist. Dummy/test entries
are hidden from discovery while stored flows can still resolve their names.

New passive capabilities:

| Capability | Evidence and limits |
| --- | --- |
| Domain → logged certificates | crt.sh, at most 10 input domains and 100 certificate relationships per run. Log entries do not prove live endpoint deployment. |
| Certificate → domains | Extract supplied SAN/common names locally; at most 500 domains, wildcard names excluded. |
| Domain → DNS dependencies | VirusTotal indexed NS/MX/CNAME, at most 25 domains and 100 records per domain; requires a VirusTotal key. |
| CIDR → routing history | RIPEstat dated routing origins, default last 30 days; requested interval at most 366 days, 10 input prefixes and 100 intervals. |

CIDR expansion now supports `preview_only="true"` and string `max_results`
(default `"256"`, maximum `"4096"`). Oversized ranges are reported as partial;
the enricher never materializes an entire large network before applying its cap.
Copilot use applies tighter per-action input limits and string parameters.

## Provider reuse and partial results

VirusTotal responses are reusable for one hour, Shodan responses for 15 minutes,
scoped to the provider credential. Enable **Refresh** to request fresh evidence;
refresh does not bypass shared cooldowns. Evidence cards show cached reuse and
the original retrieval time and source scan. Provider observation dates remain
distinct from retrieval dates.

Concurrent requests share a credential-level lease. A request that cannot obtain
it within five seconds reports partial and can be retried later. Configured Redis
unavailability stops these lookups rather than making uncoordinated provider calls.
Authentication and quota failures stop the affected batch. Transient retries are
bounded; streamed JSON responses are capped at 4 MiB.

Graph imports commit in batches. If a later batch fails, the scan reports partial
and the count of confirmed graph operations; returned result counts are separate.
Interrupted scans explicitly show when the final graph commit is uncertain.
Duplicate task delivery reuses saved scans without repeating provider requests.
